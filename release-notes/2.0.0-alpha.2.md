# TechBench V2 2.0.0-alpha.2

Completes the server-backed V2 client conversion:

- Moves clients, tickets, work entries, Personal Notes, links, drafts, templates, Common Links, application settings, posting history, synchronization state, imports, and audit state to the shared `TechBench` SQL Server database.
- Replaces the production SQLite repository with the SQL Server stored-procedure repository throughout the WPF client.
- Excludes SQLite code, packages, and native assets from production builds.
- Keeps only non-business device preferences and the non-secret SQL endpoint in local JSON.
- Keeps WHD and Sage secrets protected in the V2 Windows Credential Manager namespace.
- Uses Windows Integrated Authentication and Active Directory-backed database roles; no TechBench or SQL password is entered by users.
- Adds schema-version-2 optimistic concurrency, owner-private Personal Notes, durable posting attempts/leases, synchronization leases, and server-side import/mapping state.
- Restores the original built-in note templates and Common Links as shared server defaults.
- Preserves deliberate manual posting verification and Sage draft tracking through audited server operations.
- Preserves V1 unchanged and retains the separate V2 executable, installer, package identity, and automatic-update feed.

This release requires the matching SQL Server 2016 schema-version-2 deployment. The database and client must be upgraded together; alpha.1 and alpha.2 should not be mixed during normal use.

Alpha.2 remains a deployment candidate until the complete upgrade and domain-user workflows pass smoke testing on the actual SQL Server 2016 instance.
