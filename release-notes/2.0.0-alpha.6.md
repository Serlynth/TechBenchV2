# TechBench V2 2.0.0-alpha.6

## WHD sync service deployment

- Moves organization-wide WHD reads out of Admin workstations into a dedicated Windows service; personal WHD note/status posting remains user-scoped in the client.
- Adds schema version 6 with a durable serialized work queue, renewable leases, request-level health, a monotonic overlapping delta cursor, and transactionally applied WHD JSON batches.
- Performs an initial full ticket/reference import, scheduled ticket deltas, and daily clients/statuses/technicians/group-membership refreshes. Ticket omission never implies closure or deletion.
- Adds Admin-only Sync Now, service-health, WHD service configuration, and audited AD-user-to-WHD-technician mapping/removal controls.
- Restricts ordinary WHD ticket reads and writes to the user's mapped direct assignments and synchronized group assignments; Admins can view all tickets. A SQL Server row-level-security policy protects indirect paths such as ticket-linked work entries and V1 import references as well as the primary ticket procedures.
- Preserves the shared WHD-to-Sage customer identity when the service updates clients and uses WHD locations as the customer boundary when ticket data supplies a location.
- Adds a self-contained `win-x64` publish script for `TechBench.SyncService` and a versioned server package that carries its installer tooling plus the matching standalone schema-version-6 SQLCMD deployment.
- Adds elevated install and uninstall tooling for the `TechBenchWhdSync` Windows service, supporting a supplied domain service account or gMSA.
- Protects the service data path with explicit SYSTEM, Administrators, and service-identity access controls, while the service binaries remain under Program Files.
- Configures the Windows service for automatic delayed start, a descriptive SCM entry, and restart recovery after failures.
- Adds interactive WHD credential provisioning that pipes the secret to the executable over standard input and stores it using machine-scoped DPAPI. No WHD secret is embedded in packages, scripts, configuration, or release notes.
- Maps the prepared CSRI deployment directly to the `CSRI\TechBench_Sync` service account; no same-named AD group is required.
- Defers V1-import constraint and index binding until after `ConflictCount` is added, allowing an existing schema-version-4 SQL Server 2016 database to upgrade cleanly.
- Updates the V2 client to require SQL schema version 6. Existing alpha clients and schema version 5 must not be mixed with this build.

See `docs/WHD-SYNC-SERVICE.md` for package, installation, credential rotation, verification, and removal procedures.
