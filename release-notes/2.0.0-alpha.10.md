# TechBench V2 2.0.0-alpha.10

## Server Manager launch reliability

- Replaces the direct PowerShell Start Menu target with a consoleless launcher that starts 64-bit Windows PowerShell 5.1 in STA mode and requests administrator access.
- Shows a visible error dialog when startup or elevation fails instead of briefly opening and closing a command window.
- Records elevated startup diagnostics only in the protected `%ProgramData%\CSRI\TechBench Server Manager\startup-errors.log`; failures detected before elevation may use the current user's Local AppData or Temp directory as a fallback.
- Verifies and repairs the installed launcher files, icon, and Start Menu shortcut when Server Manager opens. This provides a recovery path after an alpha.9 Manager installs alpha.10 but leaves the old shortcut in place.

## Notification-area behavior

- Adds a TechBench notification-area icon while Server Manager is running.
- Minimizing hides the Manager; double-clicking the icon or selecting **Open TechBench Server Manager** restores and activates it.
- Selecting **Exit**, or closing the window with X, exits normally. Exit is blocked while a service or update operation is active.
- Shows one brief notification the first time the Manager is minimized, then remains quiet.
- Prevents a second Manager instance from racing the hidden tray instance, and clears/remasks all typed credential fields whenever the window is hidden.

## Update integrity

- Treats the Manager script, PowerShell launcher, consoleless VBScript shim, and CSRI icon as a transactional companion set during routine updates.
- Journals every companion's staged and rollback locations so interrupted updates can complete or restore the entire set safely.
- Loads the displayed icon from an in-memory clone so its installed file can be replaced without a lingering file handle.
- Rejects unsafe ProgramData reparse points or unexpected legacy service-data contents before privileged file operations, and reduces the service identity's credential-directory access to read-only.
- Uses unpredictable create-new temporary files for machine-protected WHD and Sage credential replacement.

## Deployment notes

- Requires database schema version 7. Alpha.10 introduces no database migration.
- Existing machine-protected WHD/Sage secrets, SQL-owned settings, service identity, and service running/stopped state remain preserved by routine updates.
- Alpha packages are not digitally signed. Verify the published SHA-256 sidecars and package manifest before installation; those checks establish byte integrity but are not a Windows publisher signature.
