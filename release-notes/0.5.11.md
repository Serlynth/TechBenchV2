# TechBench 0.5.11

This release fixes the server-owned Credentials workbook synchronization introduced with schema version 8.

## Fixed

- The Credentials queue is now claimed by the dedicated `tb_role_sync_service` identity. Previously, the claim procedure incorrectly required the legacy workstation sync-operator role, so the server polled continuously while requests remained queued with zero attempts.
- SQL verification and automated tests now enforce the dedicated service-role authorization boundary and reject a regression to `EnsureCurrentUser` in the Credentials claim procedure.

## Also included

- Server Manager and client-facing terminology uses **Credentials** instead of the workbook filename.
- Credential reveal and copy operations do not create an application audit trail.
- The Credentials workbook path remains an Admin-only server setting and is not embedded in release artifacts.

## Upgrade order

1. Apply `TechBenchV2-SQLServer2016-0.5.11.sql` in SSMS with SQLCMD Mode enabled.
2. Run `TechBenchServerSetup.exe` as Administrator on the service host.
3. Open Server Manager, confirm the service is running, and select **Credentials > Sync now**.
4. Install `TechBenchV2Setup.exe` on workstations or use the client updater.

Version 0.5.11 continues to use SQL schema version 8. Existing encrypted credential records, protected workbook password, server configuration, and queued synchronization request are preserved.
