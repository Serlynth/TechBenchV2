# TechBench V2 2.0.0-alpha.5

## V1 migration boundary

- Adds schema version 5 and an owner-scoped TechBench V1 import contract.
- Adds **Settings > Import V1 Database...** for every authenticated TechBench user, with a per-user preview and completion report.
- Opens the selected closed V1 database read-only, checks its SQLite integrity/schema, and rejects active sidecars or a file that changes during the read.
- Bundles the SQLite runtime only for that read-only migration reader; V2 still has no local/offline business database and never packages a `.db` file.
- Every normal TechBench user can import only into work records owned by their authenticated Windows SID; import procedures never accept a caller-supplied owner.
- Repeated and partially retried imports are idempotent by AD owner, `TechBenchV1` source, entity type, and legacy ID.
- A resumed active batch continues to report mappings first accepted by that batch as imported; unchanged mappings from an earlier batch are skipped.
- A changed legacy row is reported as a conflict and is never allowed to overwrite an earlier SQL import silently.
- Equivalent V1 link rows may map to the same canonical SQL relationship; work-entry and posting-log reverse mappings remain unique.
- Links and posting logs attach only through work-entry mappings accepted by the current batch, preventing an omitted or conflicted row from being reached through stale history.
- Preserves work-entry timestamps, private notes, WHD/Sage posted state and timestamps, Sage ticket numbers, work-entry relationships, and posting-log history. A successful legacy posting log also repairs missing posted flags/timestamps and recomputes posting status conservatively so an already-posted item is not sent again.
- Successful completion requires exactly one outcome for every read item and zero errors.
- Any user may abandon only their own stale active V1 batch; passing no batch ID selects that user's current active V1 batch, and the recovery is audited.
- Adds an ordinary-user read-only SQL resolver for exact source-qualified client/ticket identities, Sage customer IDs, and unambiguous organization aliases or client names. It queries authoritative tables directly rather than fuzzy or capped list procedures and reports explicit resolution status.
- Leaves shared clients, tickets, aliases, Common Links, templates, common tags, and organization settings unchanged.
- Excludes credentials, editor drafts, active posting attempts, and other unsafe device/operational state.

## Deployment

This client requires the matching SQL Server 2016 schema-version-5 deployment. Have the DBA back up `TechBench`, rerun the complete standalone SQLCMD deployment, and install alpha.5 as one coordinated test cutover. The V1 database remains unchanged by the server import contract.
